# Development

All commands run from the repository root. `uv run` executes a command inside the
project environment (`.venv`), creating or updating it first if needed.

## Everyday commands

| Task | Command |
|---|---|
| Install / update the environment after a pull | `uv sync` |
| Run the tests | `uv run pytest` |
| Tests with coverage | `uv run pytest --cov` |
| Run every check (format, lint, types, file names, …) | `uv run pre-commit run --all-files` |
| Format the code | `uv run ruff format` |
| Lint and auto-fix | `uv run ruff check --fix` |
| Type check | `uv run mypy` |
| Preview the docs at <http://127.0.0.1:8000> | `uv run mkdocs serve` |
| Add a dependency | `uv add pandas` (or `uv add --group dev <tool>` for a dev tool) |
| Upgrade locked versions | `uv lock --upgrade` |

## The tools

**uv** manages Python, the virtual environment and dependencies. `pyproject.toml`
lists what the project needs; `uv.lock` records the exact versions so every machine
and CI get the same environment. Commit both. `.python-version` (3.13) sets the
Python used locally; the package supports 3.11 and newer.

**Ruff** formats the code (like Black) and lints it (like Flake8, isort and pyupgrade
together). Its rules are in `[tool.ruff]` in `pyproject.toml`.

**mypy** checks the type hints in strict mode (`[tool.mypy]`). New functions need type
hints on their arguments and return value.

**pytest** runs `tests/` and the `>>>` examples in the docstrings under `src/`.

**pre-commit** runs, before each commit: whitespace and file checks, Ruff, the
`uv.lock` consistency check, mypy, and `destest check-names` on any changed file in
`Result data/`. If a hook changes a file (formatting, a trailing newline), the commit
stops; review the change, `git add` it and commit again. Skip once in an emergency with
`git commit --no-verify`.

**GitHub Actions** run the same checks on every push to `main` or `dev` and on every
pull request (`.github/workflows/ci.yml`): the pre-commit hooks on all files, and the
tests on Python 3.11–3.14 (Linux) and 3.13 (Windows).

**MkDocs + Material** build this site from `docs/` and the docstrings in `src/`
(the [API reference](reference.md) is generated by mkdocstrings). Pushes to `main`
publish it to GitHub Pages (`.github/workflows/docs.yml`).

!!! note "Docs tooling"
    Material for MkDocs is in maintenance mode; its authors are building the successor,
    Zensical, which reads the same `mkdocs.yml`. Moving later should mostly mean swapping
    the build command. MkDocs is pinned below 2.0 because MkDocs 2 is an incompatible rewrite.

## One-time setup on GitHub

1. **Pages:** *Settings → Pages → Build and deployment → Source: GitHub Actions.*
   The site appears at <https://hichamjohra.github.io/DESTEST_3.0/> after the next push
   to `main`. (Pages on a private repository needs a paid GitHub plan.)
2. **Branch protection (optional):** *Settings → Branches → add rule for `main` →
   Require status checks to pass* and select the CI jobs, so nothing is merged with
   failing tests or badly named result files.
